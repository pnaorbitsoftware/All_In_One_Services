## Pass 6 — socket error log spam

The repeated `[Socket] Connection error: timeout` / `websocket error` lines are the *expected* symptom of the still-unresolved production backend issue from Pass 5 (deployed backend missing Socket.IO route) — socket.io's automatic reconnection was retrying the last known candidate and logging `console.error` on every single attempt. **This will keep happening until the backend in this zip is actually deployed** — no client-side code change can make a socket connect to a server that doesn't serve that route. What I *could* fix, and did:

- `socket.on("connect_error", ...)` now logs only the **first** failure per candidate URL instead of once per retry attempt — `reconnectionAttempts` still retries in the background (lowered from 10 to 4 to reduce wasted network attempts against a known-dead endpoint), but it no longer floods the console with identical repeated lines.
- Once every candidate has been tried and failed, logs **one** final, clear message explaining real-time features are disabled and why, then lets the app continue working normally via manual refresh/polling (which was already the fallback behavior — booking/notification data still loads via regular API calls, only *live push* updates need the socket).
- Downgraded from `console.error` to `console.warn`, since a socket reconnect failure is a recoverable/expected condition when a backend isn't deployed yet, not an application crash.

**This does not make the socket connect** — it only stops the noisy repeated logging of a condition that's genuinely still true (no reachable Socket.IO backend). The only real fix for the connection itself is deploying this zip's `backend/` folder (see Pass 5).
